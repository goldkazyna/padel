## 2026-07-27

### Фикс: недельное расписание (по дням) падало в 500
- Blade-ошибка «unexpected endif»: в карточке брони недельного вида директива `@if` была приклеена вплотную к `@endif` (`…@endif@if($ecW['paid']…)`). Blade не распознаёт `@if`, если перед `@` стоит словосимвол (регексп `\B@`), поэтому `@if` оставалась текстом, а её `@endif` компилировался → повисший `endif` → фатальная ошибка при рендере всей страницы. Добавлен пробел: `@endif @if(…)`. Баг был только в `schedule_week.blade.php` (в `schedule.blade.php` таких склеек нет — поэтому «по кортам» работало). Только код, деплой без миграций (`php artisan view:clear`).

### Длительность брони до 12 часов
- В модалке бронирования корта кнопки длительности расширены с 1–6 до **1–12 часов**. Фронт: кап `Math.min(maxSlots, 6)` → `12` (оба вида расписания), редактирование `max < 8` → `max < 12`. Бэкенд: валидация `slots` `max:8` → `max:12` в `book()` и `update()`. Фактическое число кнопок ограничено доступностью до закрытия корта. Только код, деплой без миграций.

### Фикс: нельзя было заблокировать слот 23:00
- Для последнего слота `calcBlockEndTime()` в расписании отдавал конец **«24:00»**, а бэкенд-валидатор (`date_format:H:i`) его отклонял → блокировка молча не создавалась. Обычные брони конец 23:00-слота хранят как **«00:00»** (Carbon addHour), `canBook` это корректно обрабатывает (если конец ≤ начала, +24ч). Поправил `calcBlockEndTime` на `(h + slots) % 24` → отдаёт «00:00». Исправлено в **обоих** видах расписания: `schedule.blade.php` и `schedule_week.blade.php`. Только код, деплой без миграций.
