# Лиги: серия турниров с общей таблицей

Организатор создаёт лигу («Сентябрь Кап»), внутри неё — 8 этапов формата
Americano Flex. Игроки записываются один раз в лигу и играют все этапы.
Есть сводная таблица по лиге и таблица каждого этапа отдельно.

## Решения (согласованы 2026-08-29)

| Вопрос | Решение |
|---|---|
| Чем сортируется таблица лиги | **Сумма забитых очков за все этапы** |
| Пропуски этапов | Всё в зачёт, пропустил — получил ноль |
| Замены | Очки идут тому, кто реально играл |
| Запись | Записываются в лигу, состав едет во все этапы |

Внутри этапа ничего не меняется: Flex считается как сейчас
(`AmericanoFlexRanking`: среднее → % побед → личная встреча → рейтинг).
Рейтинг Elo начисляется каждым этапом как обычным турниром.

## Почему именно так

**Сумма, а не среднее.** Внутри одного турнира Flex ранжирует по среднему,
потому что у игроков разное число матчей из-за отдыхов. В лиге же смысл
другой: приходить на этапы — часть соревнования. Сумма честно наказывает
пропуски, и её понимает любой игрок без объяснений.

**Тай-брейки остаются флексовыми.** При равной сумме сравниваем в том же
порядке, что и внутри этапа: % побед → личная встреча (по всем этапам) →
рейтинг → id. Иначе два человека с одинаковой суммой встанут «как повезёт».

**Лига не хранит результаты.** Сводная таблица считается на лету из этапов.
Отдельная таблица результатов начала бы расходиться с этапами при первой же
правке счёта задним числом — а счёт правят регулярно.

## Данные

```
leagues
  id, club_id, creator_id
  name, description, cover
  status: draft | open | in_progress | completed | cancelled
  format: americano_flex          — пока единственный, поле на вырост
  stages_planned: 8               — сколько этапов задумано (для «Этап 3 из 8»)
  start_date, end_date
  min_level, max_level, max_players, price
  is_rated                        — этапы начисляют рейтинг
  created_at, updated_at

tournaments
  + league_id  (nullable)         — этап принадлежит лиге
  + league_stage (nullable)       — номер этапа: 1..8

league_players
  id, league_id, user_id
  status: registered | pending | left
  joined_at, left_at
  unique(league_id, user_id)
```

Турнир без `league_id` — обычный турнир, как сейчас. Ничего в существующих
таблицах не переписывается.

## Как считается сводная таблица

Собираем агрегаты по всем **завершённым** этапам лиги (незавершённые в
таблицу не идут — как и в статистике игрока):

```
на игрока: очки забитые, очки пропущенные, матчи, победы, поражения, ничьи,
           этапов сыграно, лучшее место на этапе
сортировка: сумма очков → % побед → личная встреча → рейтинг → id
```

Матчи 0:0 не считаются сыгранными — правило то же, что в `AmericanoFlexRanking`.

Замена, сыгравшая один этап, попадает в таблицу со своими очками и пометкой
«сыграл этапов: 1». Это честно: очки заработал он.

## Экраны

**Веб-CRM**

1. `/club/leagues` — список лиг клуба: название, период, этапов сыграно из
   запланированных, участников, статус.
2. `/club/leagues/create` — создание: название, описание, число этапов,
   период, уровни, цена, лимит участников.
3. `/club/leagues/{id}` — карточка лиги с вкладками:
   - **Этапы** — список турниров лиги, кнопка «Добавить этап» (создаёт
     Americano Flex с предзаполненными настройками и привязкой к лиге),
     переход в обычную страницу турнира;
   - **Таблица** — сводная таблица лиги, та же вёрстка, что у Flex, плюс
     колонка «этапов сыграно» и выгрузка картинкой;
   - **Участники** — состав лиги, добавить/убрать, поиск игроков (уже умный).

**Приложение (игрок)**

4. Карточка лиги в списке турниров — отдельным видом, с подписью
   «Лига · 8 этапов».
5. Экран лиги: шапка, кнопка «Записаться в лигу», вкладки «Этапы»,
   «Таблица», «Участники». Тап по этапу открывает обычный экран турнира.
6. В деталях этапа — плашка «Этап 3 из 8 · Сентябрь Кап» со ссылкой на лигу.

**Приложение (админ)**

7. Лига в списке админских турниров, создание этапа из лиги, правка состава
   этапа перед стартом.

## Порядок работ

**Этап 1 — фундамент и веб (основной объём)**
Миграции, модели `League` / `LeaguePlayer`, сервис сводной таблицы
`LeagueStandings`, CRUD лиги в CRM, привязка турниров, состав, таблица.
Тесты: сумма по этапам, тай-брейки, незавершённые этапы не в зачёте,
замена попадает в таблицу, пропуск = ноль.

**Этап 2 — приложение (игрок)**
API лиги (`/leagues`, `/leagues/{id}`, `/leagues/{id}/standings`,
`/leagues/{id}/register`), экран лиги, запись, плашка этапа в турнире.

**Этап 3 — админка в приложении и мелочи**
Создание этапа из приложения, правка состава, пуш «Этап 4 через 2 дня»,
выгрузка таблицы картинкой, страница лиги для шаринга.

## Что сделано (на 30 августа 2026)

Все три этапа плана закрыты и выкачены на прод. Ниже — что реально работает,
чтобы не переоткрывать заново.

**Бэкенд и данные**
- `leagues`, `league_players`, `tournaments.league_id` + `league_stage`;
  миграции `2026_08_29_000001_create_leagues_tables`,
  `2026_08_30_000001_add_stage_defaults_to_leagues` — накатаны.
- `App\Services\LeagueService` — единая логика для веба и приложения:
  `createStage`, `fillFromLeague`, `refillStage`, `deleteStage`,
  `renumberStages`, `addPlayer`, `removePlayer`.
- `App\Support\LeagueStandings` — сводная таблица на лету по завершённым
  этапам: сумма очков → % побед → личные встречи → рейтинг → id.

**Веб-CRM**
- Раздел «Лиги»: список, создание, редактирование, карточка с вкладками
  «Таблица / Этапы / Состав» на общих компонентах CRM.
- Формат этапов задаётся в лиге один раз (корты, длительность, очки, парность,
  проверенный уровень, чат), парность можно переопределить на этапе.
- Состав: поиск игроков, кнопка «Добавить тестовых игроков», удаление.
- Этап: создание, удаление несыгранного с перенумерацией, плашка «Этап N лиги»
  на странице турнира с кнопкой «Обновить состав из лиги».
- Парный флекс: сбор пар в два клика с авто-раскладкой; старт турнира
  открывается только по сохранённым парам.

**Приложение (игрок)**
- Секция «Лиги» над списком турниров, карточка в дизайне карточки турнира
  (логотип клуба, формат, цена, шкала этапов, ближайший этап).
- Экран лиги: шапка с логотипом и форматом, вкладки «Таблица / Этапы»,
  сводная таблица тем же виджетом, что таблица этапа (скролл вбок, галочки
  верификации, подсветка своей строки, колонка «Э»).
- Этапы: медаль за 1–3 место или номер места, «моё место N · очки», тап по
  сыгранному этапу открывает его как турнир из истории (таблица, разбор AI).
- «Мои лиги» в профиле = состав лиги + лиги, где играл на замене.
- Этапы лиги убраны из общей истории турниров.

**Приложение (админ клуба)**
- Раздел «Лиги»: создание, этапы (с парностью и удалением), состав, таблица.
- Замена участника правит и собранную пару; кнопка «Обновить состав» в этапе.

**Правила** — в `docs/SYSTEM_RULES.md`, раздел «Лиги (серия этапов)».
**Тесты** — `LeagueCrmTest`, `LeagueStandingsTest`, `MobileLeagueApiTest`,
`MobileAdminLeagueTest`, `LeagueStageRosterTest`, `FlexPairBuilderTest`.

## Что доделывать дальше

Ничего из этого не начато — список для следующего захода.

- **Постоянные пары в парной лиге.** Сейчас пары собираются заново на каждом
  этапе. Механики «пара на всю лигу» нет, и это заметно на парных лигах.
- **Уведомления по лиге:** пуш «Этап 4 через 2 дня», напоминание составу лиги
  при создании этапа.
- **Шаринг:** выгрузка сводной таблицы картинкой (как у турниров) и публичная
  страница лиги.
- **Оплата лиги целиком** вместо поэтапной (цена сейчас лежит и в лиге, и в
  этапе, списывается по этапам).
- **Завершение лиги:** статус `completed` ставится только руками; авто-финиша
  после последнего этапа и итогового экрана «победитель лиги» нет.
- **Награды за лигу** — сейчас награды только на уровне турнира.
- **Колонка «место на этапе» по каждому этапу** (матрица 8 колонок) — красиво,
  но на телефоне узко; решить, нужна ли.
