# Спека: чат внутри турнира (черновик, отложено)

Статус: **обсуждено, не реализовано.** Вернёмся позже. Документ фиксирует
принятые решения и план, чтобы ничего не потерять.

## Цель

Внутри турнира — чат, где участники общаются. На «закрытом» чате (когда не
открыт) — бейдж непрочитанных сообщений.

## Выбор подхода (важно)

Рассмотрели 3 варианта:

| Вариант | Суть | Вердикт |
|---|---|---|
| **Поллинг + REST** | экран раз в ~3 сек тянет новые сообщения, push когда закрыто | ✅ **выбрано для старта** |
| Firestore | real-time через Firebase, без своего вебсокет-сервера | запас на будущее (если нужен 0 нагрузки на свой сервер) |
| Вебсокет (Laravel Reverb) | настоящий real-time + «печатает…», но демон/порт/supervisor | избыточно сейчас |

**Почему поллинг безопасен:** нагрузка зависит НЕ от числа турниров, а от числа
людей, у кого прямо сейчас ОТКРЫТ экран чата. Неактивные/завершённые турниры → 0
запросов. Запрос `WHERE tournament_id=X AND id > :last_id` по индексу почти всегда
возвращает 0 строк (микросекунды). Поллинг идёт только пока экран открыт и
останавливается при сворачивании/уходе с экрана.

Апгрейд на Firestore/Reverb позже не ломает клиентский код чата.

## Данные

**`tournament_messages`**
- `id`
- `tournament_id` (FK, cascadeOnDelete)
- `user_id` (FK — автор)
- `body` (text)
- `created_at`
- индекс `(tournament_id, id)`

**`tournament_chat_reads`** — указатель прочтения на пользователя в чате
- `tournament_id`, `user_id`, `last_read_message_id`
- unique `(tournament_id, user_id)`

Опционально для дешёвого «есть непрочитанные»: денормализованное
`tournaments.last_message_id` (обновляется при отправке) — тогда «has_unread» =
сравнение двух чисел без COUNT.

## Эндпоинты (REST, auth:sanctum)

- `GET  /tournaments/{tournament}/chat?after_id=N` — сообщения (новые после N).
- `POST /tournaments/{tournament}/chat` `{body}` — отправить сообщение (+ push
  остальным участникам, у кого чат закрыт).
- `POST /tournaments/{tournament}/chat/read` `{message_id}` — отметить
  прочитанным (двигает указатель).
- `GET  /tournaments/chats/unread` — счётчики непрочитанного по всем чатам юзера
  (для общего бейджа). ИЛИ вшить `chat_unread`/`has_unread` прямо в ответ
  `/tournaments/my` и деталей турнира.

## Бейдж непрочитанных

- **Точка «есть непрочитанные»** = `last_message_id > my_last_read_id` (сравнение
  чисел, нулевая нагрузка).
- **Число** = `COUNT(*) WHERE id > my_last_read_id` (индексированный count).
- Не считаем свои же сообщения за непрочитанные.
- Оживает: при загрузке списка, pull-to-refresh, возврате из фона (app resume),
  опц. лёгкий поллинг счётчиков пока на экране, + push-триггер.
- Сброс: при открытии чата и долистывании до низа → `chat/read`.

## Push

Переиспользуем существующий FCM (`FCMNotificationService`). На новое сообщение —
push участникам с закрытым чатом: «Новое сообщение в чате турнира «…»». Push также
служит триггером обновить счётчик.

## Открытые вопросы (решить при реализации)

1. **Кто может писать:** только участники (registered) + организатор/клуб —
   ИЛИ любой авторизованный, кто видит турнир. (Склонялись к «участники + орг» —
   меньше спама.)
2. До какого момента жив чат: только до завершения турнира или бессрочно.
3. Модерация: удаление сообщений организатором/админом клуба.
4. Точное число в бейдже vs просто точка.

## Объём (оценка)

2 миграции + 1 контроллер (~4 метода) + Flutter: экран чата (с таймером-поллингом)
+ бейдж в карточке/списке + read-pointer. Низкий риск, без новой серверной
инфраструктуры.
