# Эскалера — экраны игрока — дизайн

**Дата:** 9 августа 2026
**Область:** игрок видит идущий турнир «Эскалера», своё место в истории и в чужом профиле.
**Репозитории:** `C:\projects\padel` (Laravel API), `C:\projects\padel_app` (Flutter).

## Что уже есть

Веб-версия и мобильная админка формата закончены. Логика живёт в
`App\Services\EscaleraService`; для расчёта дельт рейтинга там уже есть
`calculateEloForMatch(EscaleraMatch $match, array &$ratingChanges): void` —
та же сигнатура, что у `KingOfCourtService`.

Со стороны игрока формат сейчас не поддержан: `/api/mobile/tournaments/{t}/live`
отвечает 400, место в архиве не считается, матчи не попадают ни в историю,
ни в счётчики профиля.

## Ключевое наблюдение

`lib/utils/tournament_navigation.dart` уже открывает экран «Короля корта»
для Round Robin: структура live у них одинаковая — один лидерборд плюс
раунды с матчами. У Эскалеры структура такая же. Поэтому **новый экран не
пишется**: сервер отдаёт ответ той же формы, а во Flutter добавляется
`case 'escalera'` рядом с `case 'round_robin'`.

Экран читает из ответа: `tournament.format_name`, `tournament.is_paired`,
`leaderboard[].total_points`, `rounds[].my_rating_change`,
`rounds[].matches[].court_tier`, `.court_label`, `.has_me`.

## 1. Live-турнир

Новый `liveEscalera(Tournament $tournament, $user)` в
`MobileTournamentController`, по образцу `liveKingOfCourt()`.

**Раунды.** Матчи всех кортов раунда одним списком, отсортированы по номеру
корта и номеру матча. У каждого матча:

- `court_number` — номер корта;
- `court_tier` — `top` для первого корта, `bottom` для последнего,
  `middle` для остальных;
- `court_label` — `Корт N`, с пометкой `верхний` / `нижний` для крайних:
  в эскалере ярус это не украшение, а смысл — наверху сильнейшие;
- `team1` / `team2` с игроками, счётом и `has_me`;
- `has_me` на матче — играет ли в нём целевой игрок.

`rounds[].my_rating_change` — дельта рейтинга целевого игрока за раунд,
посчитанная прогонкой `calculateEloForMatch` по матчам в порядке раундов,
как это делает `finishTournament`. У нерейтинговых турниров — `null`.

**Таблица.** Из `EscaleraService::standings()`. `total_points` — метрика, по
которой идёт зачёт этого турнира: баллы за позиции при `escalera_standings_mode
= points`, сумма забитых очков при `raw_points`. Так колонка «Очки» на экране
всегда показывает то, по чему считается место, — как подсвеченная колонка в
веб-таблице. `points_for` / `points_against` — забито и пропущено отдельно,
плюс `wins`, `losses`, `point_diff`, `ball_percent`, `is_me`.

**Подсветка чужого игрока.** `live()` уже подменяет `$user` по `player_id`
из запроса — ветка эскалеры использует того же пользователя, поэтому
открытие турнира из чужого профиля подсвечивает его матчи и строку.

`is_paired` всегда `false` — пар в формате нет. `playoff` — пустой массив.

## 2. Место игрока

Ветка `escalera` в `getUserPlace()`: позиция из
`EscaleraService::standings()`. Этим закрываются сразу три экрана — архив
«Мои турниры», карточка завершённого турнира и профиль чужого игрока: все
берут место из этого метода.

## 3. Матчи и статистика

`MobileMatchController::history` собирает матчи по типам поимённо —
добавляется `EscaleraMatch` с меткой формата `escalera`.

`User::getAllMatchesStats()` — короткие матчи эскалеры в общий счётчик
сыгранных, выигранных, проигранных. Ничья допустима (счёт свободный), она
идёт в `draw`.

`User::getTournamentStats()` — `by_type['escalera']` и общий счётчик
завершённых турниров.

Замечено попутно: `by_type` не содержит `just_padel_it`, то есть турниры
этого формата не попадают в разбивку профиля. Это отдельный баг, в объём
данной работы не входит.

## Проверка

Feature-тесты в `tests/Feature/EscaleraPlayerScreensTest.php`:

- `/live` для идущего турнира отдаёт раунды, ярусы кортов и подсвечивает
  матчи игрока;
- `/live` с `player_id` подсвечивает чужого игрока, а не текущего;
- `total_points` в таблице меняется вместе с режимом зачёта;
- место в архиве совпадает с позицией в таблице;
- матчи эскалеры видны в `/matches/history`;
- счётчики профиля растут после завершения турнира.

Flutter — `flutter analyze`; автотестов в проекте нет.

## Что сюда не входит

- собственный live-экран под эскалеру: переиспользуется экран «Короля корта»;
- push-уведомления о новом раунде для игроков;
- разбивка `by_type` для Just Padel It.
