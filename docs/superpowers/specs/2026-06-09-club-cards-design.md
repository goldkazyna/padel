# Клубные карты — дизайн

**Дата:** 2026-06-09
**Платформа:** веб (Laravel + Blade), клубная админка. Мобильного UI нет.

## Цель

Дать клубам систему клубных карт: создавать типы карт, выпускать их клиентам,
автоматически списывать занятия по факту проведённых броней, видеть журнал
списаний и остатки. Карты — только для индивидуальных/корт/тренерских броней;
групповые занятия платятся пакетами участников (отдельная система) и здесь не
участвуют.

## Решения (согласовано)

- Тип карты = **одна суть**: `visits` (посещения корта), `trainer` (занятия с
  тренером), `discount_court` (скидка на корт), `discount_trainer` (скидка на тренера).
- Списание счётчиков (visits/trainer) — **по длительности в часах** (1 час = 1
  занятие, 2 часа = 2; округление к ближайшему, минимум 1).
- Скидочные карты — **просто % скидка** на цену брони, без баланса и без
  авто-списания; работают пока действует срок.
- Меню создания типов — **в клубной админке** (карты свои у каждого клуба).
- **Одна карта на бронь.**
- Группы — **исключены**.

- `club_card_id` (fk club_cards, nullable) — выбранная карта для брони.
- `card_charged_at` (timestamp nullable) — когда крон списал (защита от двойного списания).

## Логика

### Выпуск карты клиенту
Админ → Клиенты → клиент → «Привязать карту»:
- выбрать тип; остаток — вбить вручную ИЛИ взять `nominal` типа;
- срок — бессрочно или дата (по умолчанию `default_validity_days`, если задан);
- создаётся `club_card` с уникальным `code`, `initial_balance`, `balance`.

### Бронирование с картой
В окне брони после выбора клиента: если у клиента есть **актуальные** карты —
показываем выбор «Клубная карта» и остаток.
- Счётчик (visits/trainer) → `court_bookings.club_card_id` = карта (списание позже кроном).
- Скидочная (discount_court/discount_trainer) → применяем % к цене (поле `discount`)
  сразу при сохранении; `club_card_id` тоже ставим (для журнала «применена скидка»,
  опционально).
- Только индивидуальные/корт/тренер. Для групповых карта не предлагается.

### Авто-списание (крон, раз в час) — `cards:charge-due`
Берём `court_bookings` где: `status=confirmed` (не cancelled), `club_card_id` задан,
карта типа-счётчика, `card_charged_at` пуст, конец брони (`date`+`end_time`) < сейчас.
Для каждой:
- `amount` = round((endMin − startMin) / 60), минимум 1;
- `amount = min(amount, balance)` (нельзя уйти в минус);
- уменьшаем `balance`, ставим `card_charged_at = now`, пишем `club_card_transaction`.
Отменил до конца → бронь cancelled → крон пропускает → не списали. ✅

Скидочные карты крон не трогает (скидка уже применена в момент брони).

Отмена брони после списания (редкий кейс «пришёл, потом отменили») — возврат на
карту **вне scope v1** (зафиксировать как возможную доработку).

### Разделы
- **«Клубные карты»:** типы карт (CRUD) + выпущенные со статистикой
  (**выпущено всего** / **актуально сейчас**); тап → список карт по клиентам.
- **«Журнал карт»:** список списаний (карта, клиент, бронь, сколько, когда).
- **Карточка клиента:** блок «Клубные карты» — карты клиента с остатком + история
  списаний по карте; кнопка «Привязать карту».

### Защита удаления
- **Тип карты** нельзя удалить, если есть активные выпущенные карты этого типа →
  сообщение «сначала отвяжите карты от клиентов».
- **Карту клиента** можно отвязать/удалить; если есть остаток — предупреждение.

## Компоненты (изоляция)

**Модели:** `ClubCardType`, `ClubCard`, `ClubCardTransaction`.

**Сервис:** `ClubCardService` — выпуск карты (генерация кода, init баланса),
применение карты к брони (скидка/привязка), списание (используется кроном и при
ручной корректировке), проверки удаления.

**Контроллеры (Club):**
- `ClubCardTypeController` — CRUD типов.
- `ClubCardController` — выпуск/отвязка/просмотр выпущенных, статистика.
- `ClubCardJournalController` — журнал.

**Команда:** `App\Console\Commands\ChargeDueCards` (`cards:charge-due`), в расписании
hourly.

**Интеграция брони:** правки в `CourtController` (store/update) + окна брони/
редактирования в `schedule.blade.php` (выбор карты, остаток, применение скидки).

## Этапы реализации
1. **Данные + типы карт:** миграции (3 таблицы + 2 поля), модели, CRUD типов в
   меню клубной админки, защита удаления типа.
2. **Выпуск карт:** `ClubCardService::issue`, привязка к клиенту, блок в карточке
   клиента, раздел «Клубные карты» со статистикой, отвязка.
3. **Интеграция с бронью:** выбор карты в окне брони/редактирования, применение
   скидочных карт, привязка `club_card_id`.
4. **Крон + журнал:** `ChargeDueCards` (hourly), раздел «Журнал карт».

Каждый этап — отдельный набор коммитов с проверкой вживую.

## Тестирование (после реализации)
- Unit/feature: выпуск карты (код, баланс из номинала и вручную), списание по
  длительности и защита от двойного списания, скидочная карта применяет %,
  защита удаления типа, «актуальность» карты (срок/баланс).
- Ручной чек: полный цикл бронь → проведена → списано в журнал.
