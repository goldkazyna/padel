# Количество кортов у турнира: правка везде и синхронизация названий

**Дата:** 9 августа 2026
**Статус:** согласовано, готово к планированию

## Задача

Две связанные проблемы, обнаруженные владельцем.

**1. Названия кортов рассинхронизированы со счётчиком.** Админ уменьшил число кортов с 4 до 3 — счётчик стал 3, а массив названий в `tournaments.courts` остался с четырьмя элементами. Обратный случай хуже: увеличение с 3 до 5 из приложения даёт `courts_count = 5` при трёх названиях.

**2. В приложении число кортов можно менять не везде.** Поле показывается только для Just Padel It (соло), Americano Flex и командного турнира. У американо, мексикано, короля корта, Bali и кругового его нет — число кортов жёстко считается как «участники ÷ 4».

## Решения

| Вопрос | Решение |
|---|---|
| Кому открыть правку кортов | Всем типам, **кроме** Americano Flex |
| Americano Flex | Не трогаем — там уже свой ручной ввод |
| Автозначение | Участники ÷ 4, подставляется при изменении числа участников |
| Ручная правка | Разрешена: админ может переопределить автозначение |
| Рассинхрон названий | Чинится на сервере, независимо от того, что прислал клиент |

## Причина рассинхронизации

Приложение при редактировании **не отправляет** названия кортов: в `AdminService.updateTournament` (`lib/services/admin_service.dart:298`) параметра `courts` нет вовсе, экран его тоже не шлёт. Уходит только `courts_count`.

Сервер трогает массив названий, только если поле пришло — `if ($request->has('courts'))` (`app/Http/Controllers/Api/MobileAdminTournamentDetailController.php:188`). Поле не пришло, значит старый массив остаётся нетронутым.

Сейчас это мусор в данных, а не сломанная логика: длина массива нигде не определяет число кортов, оно везде берётся из `courts_count` (`app/Models/Tournament.php:490`, генераторы раундов). Названия читаются в одном месте — `Tournament::courtName()` (`app/Models/Tournament.php:735-736`), по номеру корта, поэтому лишний элемент просто не запрашивается. Но при увеличении счётчика недостающие названия уже заметны, и любой будущий код, взявший `count($tournament->courts)`, покажет неверное число.

## Архитектура

### Сервер: приведение массива к счётчику

Логика одинаковая для мобильного API и веба, поэтому выносится в модель — `app/Models/Tournament.php`:

```php
// Привести названия кортов к текущему courts_count: лишние отбросить,
// недостающие добить пустыми (подпись сгенерируется по умолчанию).
public function syncCourtNames(): void
```

Метод читает `courts_count` и `courts`, обрезает или дополняет массив до нужной длины и сохраняет. Если `courts_count` пуст — массив не трогается. Если после нормализации все элементы пусты, в поле пишется `null` — так уже делают оба контроллера.

Вызывается после сохранения турнира в трёх местах:

- `MobileAdminTournamentDetailController::update` — мобильное редактирование;
- `Club\TournamentController::store` — создание из веба;
- `Club\TournamentController::update` — редактирование из веба.

Такой подход чинит и уже испорченные записи: они выправятся при первом же сохранении турнира.

### Приложение: поле кортов для всех типов, кроме Flex

Экран редактирования `lib/screens/admin/admin_tournament_detail_screen.dart`:

- условие показа блока «Количество кортов» расширяется с трёх типов до «все, кроме `americano_flex`». У Flex остаётся собственный блок (`_isFlex`) без изменений;
- условие отправки `courtsCount` (`:294-298`) расширяется так же, иначе введённое значение не уйдёт на сервер;
- при изменении поля «Количество участников» в поле кортов подставляется `участники ÷ 4`, но только если админ не правил поле кортов сам.

Признак ручной правки — булев флаг состояния экрана, который взводится в обработчике изменения поля кортов и не сбрасывается до закрытия экрана. Программная подстановка автозначения флаг не взводит — иначе первая же автоподстановка навсегда отключила бы последующие. Если админ очистил поле кортов полностью, флаг снимается и автоподстановка снова работает.

Экран создания `lib/screens/admin/admin_create_tournament_screen.dart` приводится к тому же поведению: сейчас для не-Flex типов вместо поля выводится текст «Кол-во кортов: N (автоматически: участников ÷ 4)» (`:1126-1131`). Текст заменяется полем ввода с тем же автозначением.

### Автозначение

Берётся существующая формула `ceil(участники / 4)` (`admin_create_tournament_screen.dart:119`). При кратных четырём числах — а именно такие вводят для форматов с кортами — округление роли не играет: 16 → 4, 12 → 3, 20 → 5. Менять формулу не будем, чтобы не трогать поведение создания турниров.

Диапазон значения — от 1 до 32, как на сервере (`MobileAdminTournamentDetailController.php:98`).

## Краевые случаи

| Ситуация | Поведение |
|---|---|
| Админ уменьшил корты с 4 до 3 | Лишнее название отбрасывается при сохранении |
| Админ увеличил корты с 3 до 5 | Массив добивается пустыми, подписи «Корт 4», «Корт 5» генерируются по умолчанию |
| `courts_count` не задан | Массив названий не трогается |
| Все названия пустые | В поле пишется `null` — как уже делают контроллеры |
| Админ изменил участников после ручной правки кортов | Ручное значение сохраняется, автоподстановка не перетирает |
| Americano Flex | Поведение не меняется вовсе |

## Тестирование

Серверные фича-тесты:

- уменьшение `courts_count` обрезает массив названий;
- увеличение дополняет массив пустыми до нужной длины;
- пустой `courts_count` оставляет массив как есть;
- массив из одних пустых значений превращается в `null`;
- уже испорченная запись выправляется при первом сохранении;
- правка работает и через мобильное API, и через веб.

Прогон точечный через `--filter`: в сьюте есть давно падающие тесты, не связанные с этой работой.

Во Flutter автотестов на экраны в проекте нет — поведение приложения проверяется чтением кода и вручную.

## Вне рамок

- Валидация «участников должно быть ровно `courts_count × 4`» — она уже есть в `Tournament::canStart()` и не меняется.
- Возможность задать названия кортов из приложения — сейчас их можно вводить только при создании из веба и в приложении при создании.
- Изменение формулы автозначения.
