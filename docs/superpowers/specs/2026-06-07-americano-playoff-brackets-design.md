# Дизайн: Полуфинал для 1 группы + Нижняя сетка в Американо

**Дата:** 2026-06-07
**Репозитории:** `C:\projects\padel` (Laravel: веб + API), `C:\projects\padel_app` (Flutter)

## Проблема

В веб-форме создания турнира (`/club/tournaments/create`) для типа **Американо**:

1. При **1 группе** опция плей-офф «Полуфинал + Финал» скрыта — доступен только финал. Полуфинал есть лишь при 2 группах. На бэкенде логика полуфинала для 1 группы вообще не реализована (`AmericanoService::createSemifinalMatches()` выходит при `count($groupNames) < 2`).
2. У типа «Групповой + Плей-офф» (`team`) есть **верхняя + нижняя сетка** (чекбоксы `has_lower_bracket`, `has_bronze_match`). У Американо нижней сетки нет.

Нужно: (а) включить полуфинал для 1 группы Американо; (б) добавить Американо опцию нижней сетки — как у team.

## Решения (зафиксировано с пользователем)

- **Семантика нижней сетки:** утешительный нокаут для *следующего тира* игроков, НЕ попавших в верхнюю. Каждый игрок играет ровно в одной сетке. Структура нижней зеркалит верхнюю.
- **Объём:** обе конфигурации — 1 группа и 2 группы.
- **Сидинг новых стадий:** как в Мексикано — админ выбирает формат при создании. Нижняя сетка наследует формат верхней, применённый к её тиру.
- **Лейбл чекбокса:** «Нижняя сетка» (единообразно с team-формой).
- **Фазирование:** Фаза 1 — бэкенд + веб-рендеринг (полный прогон на вебе). Фаза 2 — мобильный рендеринг.

## Модель плей-офф

**Принцип:** нижняя сетка = копия структуры верхней для следующего тира игроков. Граница тира = размер верхней сетки.

| Конфиг | Верхняя сетка | Нижняя сетка (если включена) | Мин. игроков |
|---|---|---|---|
| 1 группа, финал | топ-4 → 1 финал | места 5-8 → 1 финал | 8 |
| 1 группа, ПФ+финал *(новое)* | топ-8 → 2 ПФ + финал | места 9-16 → 2 ПФ + финал | 16 |
| 2 группы, финал | A1+A2 vs B1+B2 | A3+A4 vs B3+B4 | 8 (по 4/гр) |
| 2 группы, ПФ+финал | топ-4 кажд. → 2 ПФ + финал | места 5-8 кажд. → 2 ПФ + финал | 16 (по 8/гр) |

**Сидинг (форматы пар):**
- Топ-8 (полуфинал): `mix` (1+8 vs 4+5, 2+7 vs 3+6), `tops` (1+2 vs 7+8, 3+4 vs 5+6), `balanced` (1+4 vs 5+8, 2+3 vs 6+7).
- Топ-4 (финал): `cross` (1+4 vs 2+3), `tops` (1+2 vs 3+4), `mix` (1+3 vs 2+4).
- 2 группы: существующие форматы (`mix`/`group_vs`/`tops`/`cross`) сохраняются для верхней; нижняя применяет тот же формат к местам следующего тира.
- В нижней сетке игроки её тира перенумеровываются (5→1, 6→2, … для 1 группы финала) и к ним применяется выбранный формат.

**Хранение:** таблица `tournament_playoff_matches` уже содержит поля `bracket` и `is_bronze` (миграция `2026_04_18_000004_add_lower_bracket_to_playoff`).
- Верхним матчам Американо проставляем `bracket = 'upper'` (сейчас не проставляется — остаётся null).
- Нижним — `bracket = 'lower'`.
- Стадии остаются русскими: `'Полуфинал'`, `'Финал'`, `'Матч за 3-е место'`.

**Матч за 3-е место** имеет смысл только в конфигурациях «ПФ + финал» (3-е место = матч проигравших полуфиналов). Для «только финал» полуфиналов нет, поэтому чекбокс «Матч за 3-е место» в форме показываем/активируем только когда выбран «Полуфинал + Финал».

**Критичный инвариант:** «чемпион турнира» и условие завершения = **финал верхней сетки**. Все запросы `where('stage','Финал')` / `where('stage','Полуфинал')`, определяющие победителя или завершение, должны быть доскоуплены `->where('bracket','upper')` (или трактовать null как upper). Иначе два финала ломают определение чемпиона и `canFinishTournament`.

**Деградация:** если игроков не хватает на нижний тир — нижняя сетка не строится; в форме показываем подсказку с минимумом участников.

## Влияние на рейтинг

Матчи нижней сетки считаются для Эло так же, как групповые и матчи верхней сетки (через `calculateEloForPlayoffMatch`). Сбор плей-офф матчей в `finishTournament`/`previewRatingChanges` уже идёт по всем `playoffMatches` со `status='completed'`, поэтому нижняя сетка попадёт в расчёт автоматически — нужно лишь убедиться, что фильтров по стадии/сетке там нет (или они не отсекают нижнюю).
