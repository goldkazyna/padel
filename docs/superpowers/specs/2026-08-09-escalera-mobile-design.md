# Эскалера в мобильном приложении — дизайн

**Дата:** 9 августа 2026
**Область:** админ создаёт и проводит турнир «Эскалера» из приложения.
**Репозитории:** `C:\projects\padel` (Laravel API), `C:\projects\padel_app` (Flutter).

## Что уже есть

Веб-версия формата закончена и работает: `EscaleraService` держит всю логику
(посев, раунды, счёт, закрытие с перемещениями, таблица, награды, рейтинг),
`Club\EscaleraController` — веб-экраны. Вся эта логика переиспользуется без
изменений; мобильная часть добавляет только транспорт и экраны.

Ключевые правила формата, от которых зависит дизайн:

- участников строго `courts_count × 4`, иначе старт заблокирован;
- на корте четверо и три коротких матча за раунд;
- счёт свободный (0–99), формат матча организаторы согласовывают сами;
- закрытие раунда записывает места и сразу создаёт следующий раунд;
- завершение турнира само закрывает открытый раунд, если все счета внесены.

## Решения владельца

1. **Экрана стартовой посадки в приложении не будет.** Старт — одна кнопка,
   посев по рейтингу. Ручная перестановка остаётся только в вебе.
2. **Экраны игрока в эту итерацию не входят.** `/live` для эскалеры
   по-прежнему отдаёт 400; игрок увидит формат следующим заходом.
3. **Выбор зачёта есть и в приложении** — `points` (баллы за позиции) либо
   `raw_points` (сумма забитых очков), как в вебе.

## Backend

### 1. Создание и редактирование

`MobileAdminTournamentController`: в правило `type` добавляется `escalera`.
Для этого типа приходит `courts_count` (2–10) и `escalera_standings_mode`
(`points` по умолчанию), а `max_participants` считается сервером как
`courts_count × 4` — присланное значение игнорируется. Это повторяет
поведение веб-формы, где число участников тоже не редактируется вручную.

`MobileAdminTournamentDetailController::update`: до старта правка кортов
пересчитывает участников тем же способом; после старта `courts_count` и
`max_participants` не меняются.

### 2. Старт

Ветка в общем `start()`: `EscaleraService::startTournament($tournament)`.
Если участников не ровно `корты × 4`, сервис возвращает `false` — отвечаем
422 с текстом, сколько игроков не хватает или сколько лишних.

### 3. Матчи и таблица

Новый `buildEscaleraMatches()` отдаёт ту же структуру, что Король корта, —
Flutter уже умеет её рисовать:

```
{
  success: true,
  type: 'escalera',
  groups: [ { id: 0, name: '', rounds: [...], leaderboard: [...] } ],
  playoff: null,
  summary: { matches_total, matches_played, all_group_matches_played,
             can_finish, can_generate_playoff: false, can_generate_next_round }
}
```

Раунд — `{ id, round_number, status, matches: [...] }`. Матчи всех кортов
раунда идут одним списком, каждый со своим `court_number`; на экране они
группируются бейджем корта — так же, как в вебе.

Строка таблицы собирается из `EscaleraService::standings()` и ложится на
существующую модель `AdminLeaderboardRow` без её изменения:

| поле ответа | источник |
|---|---|
| `total_points` | `points` — баллы за позиции |
| `points_for` | `raw_points` — забито очков |
| `points_against` | `points_against` — пропущено |
| `wins` / `losses` | одноимённые поля |
| `ball_percent` | `raw_points / (raw_points + points_against) × 100` |
| `rating` | рейтинг игрока |

`can_generate_next_round` — это `canCloseRound()`: раунд можно закрыть и
сгенерировать следующий, когда внесены все счета. `can_finish` — то же
условие ИЛИ уже закрытый последний раунд, потому что `finish` закрывает
раунд сам.

### 4. Счёт

`Route::match(['POST', 'PUT'], '/admin/tournaments/{tournament}/escalera/matches/{match}/score')`
→ `saveEscaleraScore()`. Валидация `integer|min:0|max:99` для обоих счетов,
дальше `EscaleraService::saveMatchResult()`. Один эндпоинт на сохранение и
правку: у эскалеры это одна операция.

`InvalidArgumentException` из сервиса (отрицательный счёт) → 422 с текстом,
`RuntimeException` (правка в завершённом турнире) → 422 с текстом сервиса.

### 5. Раунды и завершение

Ветка в общем `nextRound()`: `closeRound()` и сразу `generateNextRound()`.
Ветка в общем `finish()`: если раунд ещё открыт, но все счета внесены —
закрыть его, затем `finishTournament()`. Обе повторяют веб-контроллер.

## Flutter

### 1. Экран создания (`admin_create_tournament_screen.dart`)

Карточка «Эскалера» в горизонтальной ленте типов: подпись «Лестница из
кортов», иконка `Icons.stairs_rounded`.

Для этого типа:

- поле «Количество кортов» — обязательное, 2–10;
- под ним подпись «Участников будет N» (пересчёт вживую);
- поле «Максимум участников» скрыто: значение считает сервер;
- переключатель зачёта: «По баллам за позиции» / «По сумме очков».

Отдельно: сейчас число кортов подставляется автоматически как
`участники ÷ 4`. У эскалеры зависимость обратная, поэтому для неё
автоподстановка отключается — иначе поля перетирали бы друг друга.

### 2. Экран турнира (`admin_tournament_detail_screen.dart`)

Тип `escalera` включает вкладку матчей на существующем рендере групп и
раундов. Кнопка следующего раунда подписана «Сгенерировать раунд N» и
шлёт общий `next-round`; рядом «Завершить турнир». Для этого типа скрыты
пары, плей-офф и посев — их у формата нет.

### 3. Сервис (`admin_service.dart`)

`saveEscaleraScore(tournamentId, matchId, {team1Score, team2Score})` и
ветка `isEscalera` в диспетчере сохранения счёта.
