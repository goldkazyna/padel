# Выбор инвентаря в брони корта

**Дата:** 8 августа 2026
**Статус:** согласовано, готово к планированию

## Задача

В модалке бронирования корта, под блоком «Тренер», добавить выбор позиций инвентаря клуба (аренда ракетки, мячи и прочее из справочника `/club/inventory`). Выбранное считается в «Итого» брони. Работает при создании, при редактировании, в дневном и недельном расписании.

## Решения

| Вопрос | Решение |
|---|---|
| Влияние на сумму | Плюсуется к «Итого» брони |
| Количество | Да, с количеством: «− 1 +» |
| Цена позиции | Фиксируется в момент брони, снимком |
| Типы броней | Везде, кроме групповых и турнирных |
| Скидка | Применяется только к корту, инвентарь по полной цене |

### Где хранится сумма — важное уточнение

Сумма инвентаря **не входит** в `court_bookings.price`. Причина конкретная: поле «Цена корта» в модалке редактирования заполняется значением `price + discount` (`schedule.blade.php:1699` и `:1769`). Если бы инвентарь входил в `price`, при каждом открытии редактирования его стоимость попадала бы в поле цены корта и задваивалась при сохранении.

Поэтому инвентарь хранится отдельными строками — ровно так же, как уже сделано для тренеров: `court_bookings.price` содержит цену корта, `coach_price` — тренера, строки инвентаря — инвентарь. «Итого» в интерфейсе складывает всё три.

**Следствие, которое надо знать:** в отчёты по выручке (`FinanceReportService`, `ManagersReportService`) инвентарь не попадёт — они считают `price − discount`. Ровно так же сейчас не попадают деньги за тренера. Учёт продаж инвентаря в кассе и отчётах — следующий этап, вместе с остатками (см. `docs/superpowers/specs/2026-08-08-club-inventory-design.md`).

### Почему отдельная таблица, а не JSON

JSON в броне не требует миграции, но по нему не построить отчёт «сколько раз за месяц брали ракетку» и теряется связь с позицией справочника. Отдельная таблица даёт и то, и другое, и повторяет уже работающий в проекте образец `court_booking_coaches`.

### Почему хранится снимок названия и цены

Цена по решению владельца фиксируется в момент брони. Снимок названия нужен на случай удаления позиции из справочника: в старой броне останется «Аренда ракетки — 3000 ₸», а не пустая строка. Ссылка на позицию при удалении обнуляется.

## Архитектура

### Миграция

Таблица `court_booking_inventory_items`, по образцу `court_booking_coaches`:

- `id`
- `court_booking_id` — `foreignId`, `cascadeOnDelete`
- `club_inventory_item_id` — `foreignId`, nullable, `nullOnDelete`
- `name` — `string`, снимок названия на момент брони
- `price` — `integer`, снимок цены за единицу (инвентарь в целых тенге, как в справочнике)
- `quantity` — `unsignedSmallInteger`, по умолчанию 1
- таймстемпы
- индекс `club_inventory_item_id`

Уникального ключа на пару «бронь + позиция» нет намеренно: строки при редактировании пересоздаются, а одна и та же позиция в одной броне встречается один раз за счёт логики интерфейса и контроллера.

### Модели

`app/Models/CourtBookingInventoryItem.php` — `$fillable` из перечисленных полей, касты `price` в `integer`, `quantity` в `integer`, связи `booking()` и `item()`, аксессор `total` (`price * quantity`).

`CourtBooking::inventoryItems()` — `hasMany`. Плюс метод `inventoryTotal(): int`, суммирующий строки.

### Контроллер

`Club\CourtController::book` и `::updateBooking` принимают поле `inventory` — массив вида `[['item_id' => 1, 'quantity' => 2], ...]`.

Обработка вынесена в отдельный сервис `app/Services/BookingInventoryService.php`, чтобы не раздувать контроллер (он уже 1500+ строк):

```php
// Заменить строки инвентаря брони на переданный набор.
// Возвращает сумму. Позиции чужого клуба и неактивные отбрасываются.
public function sync(CourtBooking $booking, Club $club, array $rows): int
```

Метод удаляет прежние строки брони и создаёт новые, беря **текущую цену из справочника** и записывая её снимком. Позиции, не принадлежащие клубу, неактивные или с количеством меньше 1, игнорируются. Количество ограничено сверху значением 99.

Для групповых и турнирных броней сервис не вызывается — переданный инвентарь игнорируется.

Валидация: `inventory` — `nullable|array|max:50`; `inventory.*.item_id` — `required_with:inventory|integer`; `inventory.*.quantity` — `nullable|integer|min:1|max:99`. Сообщения на русском.

### Интерфейс

Три partial'а в `resources/views/club/courts/partials/`, подключаются в обе вьюхи через `@include` — копировать разметку и JS между `schedule.blade.php` и `schedule_week.blade.php` запрещено:

- `_book_inventory.blade.php` — блок в модалке создания;
- `_edit_inventory.blade.php` — блок в модалке редактирования;
- `_inventory_js.blade.php` — общие функции.

Блок выглядит как блок тренеров: заголовок «Инвентарь», сетка плиток с названием и ценой (класс по образцу `coach-btn`). Клик по плитке добавляет позицию в список выбранного под сеткой; в строке — название, кнопки «−», количество, «+», сумма и крестик для удаления. Повторный клик по плитке уже выбранной позиции увеличивает количество.

Секция получает те же классы скрытия, что и блок тренеров: `js-hide-for-group` в создании и `js-edit-hide-for-group` в редактировании — так она автоматически прячется для групповых и турнирных броней.

В зелёном блоке «Итого» добавляется строка «Инвентарь» — по образцу существующей строки «Цена за тренера» (`schedule.blade.php:632-635`), с тем же поведением: показывается, только когда сумма больше нуля.

Функции `updateFinalPrice()` (`:1245`) и `updateEditFinalPrice()` (`:1271`) дополняются слагаемым инвентаря.

Данные о позициях приходят во вьюхи из контроллера как `$inventoryItems` — активные позиции клуба, отсортированные по названию. Передаются в оба метода, `schedule` и `scheduleWeek`, симметрично.

При открытии брони на редактирование выбранный инвентарь подставляется из `$bookingInventory` — карты `booking_id → [{item_id, name, price, quantity}]`, собранной для видимого диапазона дат.

## Краевые случаи

| Ситуация | Поведение |
|---|---|
| Позицию выключили в справочнике | В старых бронях остаётся, в новых не предлагается |
| Позицию удалили из справочника | Строка брони живёт со снимком названия и цены |
| Цену позиции изменили | Старые брони сохраняют прежнюю цену |
| Бронь стала групповой или турнирной при редактировании | Строки инвентаря удаляются |
| Количество уменьшили до нуля | Позиция убирается из списка |
| У клуба выключен модуль `inventory` | Блок не показывается, переданный инвентарь игнорируется |

## Тестирование

Фича-тесты:

- бронь с двумя позициями сохраняет обе строки, `inventoryTotal()` равен сумме с учётом количества;
- цена берётся снимком: после изменения цены в справочнике строка брони не меняется;
- позиция чужого клуба отбрасывается;
- неактивная позиция отбрасывается;
- при редактировании строки заменяются, а не задваиваются;
- для групповой и турнирной брони инвентарь игнорируется;
- при выключенном модуле `inventory` инвентарь игнорируется;
- страница расписания отдаёт активные позиции клуба, дневная и недельная одинаково.

Прогон точечный через `--filter`: в сьюте есть давно падающие тесты, не связанные с этой работой.

## Вне рамок

- Остатки на складе и их списание.
- Попадание выручки за инвентарь в отчёты и кассу.
- Отдельный статус оплаты инвентаря (как у тренера).
- Отображение инвентаря в плитке слота расписания.
