# Ручное списание клубных карт — дизайн

**Дата:** 2026-06-21
**Статус:** утверждён, готов к плану реализации

## Проблема

Сейчас клубные карты-счётчики списываются **автоматически**: крон-команда
`cards:charge-due` (`bootstrap/app.php`, `->hourly()`) находит завершённые брони
с привязанной картой и вычитает часы из баланса. Админ может ошибиться при
создании брони (не та карта/не тот клиент) и не успеть отменить — крон спишет
сам. Нужен контроль: списание только по явному действию админа.

Аналог уже есть в **групповых занятиях**: там нет крона, статус «можно
проводить» считается живым запросом, а списание происходит только когда админ
жмёт «Провести занятие». Делаем карты по той же модели.

## Цель

Списание клубных карт-счётчиков становится **ручным**. Никакая фоновая задача
не вычитает баланс. Админ видит очередь «к списанию» и по каждой брони решает:
списать или пропустить.

## Поведение

### Убираем авто-списание
- Снимаем `cards:charge-due` с расписания в `bootstrap/app.php` (удаляем блок
  `$schedule->command('cards:charge-due')->hourly()`).
- Сам класс команды `App\Console\Commands\ChargeDueCards` оставляем в коде
  (не вызывается автоматически; пригоден для ручного запуска при необходимости).

### Точка входа (UI)
- В разделе **«Клубные карты»** (`/club/cards`) — кнопка **«К списанию»** с
  **бейджем**, показывающим число броней, ожидающих списания.
- Тап по кнопке → экран/список **«К списанию»**.

### Очередь «К списанию» (живой запрос, без крона)
Источник — `CourtBooking`, удовлетворяющие всем условиям:
- задан `club_card_id`;
- карта — **счётчик** (`ClubCardType::isCounter()`); скидочные карты исключаем
  (списывать нечего);
- `status = 'confirmed'`;
- время окончания брони **уже прошло** (по TZ клуба, как в `ChargeDueCards::ended()`);
- `card_charged_at IS NULL` (ещё не обработана).

По каждой брони в списке: клиент, карта (код/тип), дата + время, **часов к
списанию**, текущий **остаток** карты.

Скоуп — только брони своего клуба (через `getClub()` / корты клуба, как в
остальных club-контроллерах).

### Действия по брони
- **«Списать»** → `ClubCardService::chargeBooking($booking)` (существующий,
  идемпотентный, в минус не уходит): вычитает часы, создаёт
  `ClubCardTransaction` (`amount = -часы`), ставит `card_charged_at`.
- **«Не списывать»** → новый `ClubCardService::skipBooking($booking)`: помечает
  бронь обработанной (`card_charged_at = now()`) **без** вычитания и создаёт
  `ClubCardTransaction` с `amount = 0`, `note = 'Не списано (пропущено)'` для
  аудита. Бронь уходит из очереди.

Обе операции убирают бронь из живого запроса (по `card_charged_at`).

## Реализация

### Backend
- **`ClubCardController`**:
  - метод очереди (рендер списка + счётчик для бейджа);
  - `charge(CourtBooking $booking)` — делегирует в `ClubCardService::chargeBooking`;
  - `skip(CourtBooking $booking)` — делегирует в `ClubCardService::skipBooking`;
  - проверка принадлежности брони клубу (403 иначе).
- **`ClubCardService`**:
  - переиспользуем `chargeBooking()`;
  - добавляем `skipBooking(CourtBooking): ?ClubCardTransaction` (идемпотентно:
    если `card_charged_at` уже стоит — no-op).
  - выносим общий критерий «ожидает списания» в переиспользуемый scope/запрос,
    чтобы бейдж, список и проверки шли из одного места.
- **Маршруты** под `club.cards.*` (фича-гейт как у остального раздела карт).
- **Бейдж**: счётчик ожидающих списания в шапке раздела «Клубные карты».

### Что НЕ трогаем
- Логику `chargeBooking()` (она уже корректна и идемпотентна).
- Привязку карты к брони при бронировании (`club_card_id` ставится как раньше).
- Скидочные карты (в очередь не попадают, отдельной обработки не требуют).

## Тесты
- «Списать» вручную вычитает часы и пишет транзакцию `-часы`.
- «Не списывать» ставит `card_charged_at` без вычитания, пишет транзакцию `0`.
- Скидочные карты не попадают в очередь.
- Идемпотентность: повторные «списать»/«не списывать» не двойного эффекта.
- Очередь содержит только завершённые `confirmed` брони своего клуба со
  счётчик-картой и `card_charged_at IS NULL`.
- Чужой клуб → 403.
- (Регрессия) `cards:charge-due` снят с расписания — авто-списания не происходит.

## Деплой
- Чистый код + (возможно) ничего в БД, если не добавляем колонок. Поля
  `card_charged_at`, транзакции — уже существуют.
- На проде: `git pull` + `php artisan config:clear`. Крон-расписание обновится
  автоматически из `bootstrap/app.php` (отдельных действий не нужно, если
  планировщик читает приложение; системный `* * * * * artisan schedule:run`
  не меняется).
