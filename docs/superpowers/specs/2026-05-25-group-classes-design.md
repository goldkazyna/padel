# Групповые занятия (CRM) — дизайн

**Дата:** 2026-05-25
**Статус:** согласован к реализации
**Затрагивает:** backend `C:\projects\padel` (Laravel, веб-админка клуба). Приложение НЕ затрагивается.

## Цель

Дать клубам вести **групповые занятия**: создавать именованные группы, добавлять в них клиентов с предоплаченным пакетом занятий, планировать занятия (сессии) с занятием корта в общем расписании и регистрировать проведение + посещаемость со списанием занятий из пакета.

## Согласованные решения

- **Scope:** только веб-админка. Приложение/самозапись игроков — НЕ в этом этапе.
- **Сессии:** разовые (создаются по одной). Авто-повтор/расписание групп — НЕ в этом этапе.
- **Участники:** добавляет админ/модератор из CRM-клиентов (`club_clients`).
- **Оплата:** предоплата за пакет. При добавлении клиента в группу с N занятиями фиксируется оплата `N × цена_за_занятие` (оплачено/нет). Каждое посещение списывает 1 занятие из остатка.
- **Параметры сессии:** у группы есть тренер по умолчанию, но корт/дата/время/тренер выбираются на каждое занятие отдельно.
- **Посещаемость:** отмечается ТОЛЬКО в разделе «Журнал занятий». Расписание показывает слот занятым, но посещаемость там не трогаем.
- **Нулевой остаток:** отметить «пришёл» нельзя — сначала «продлить» (новый пакет).
- **Вместимость группы:** опциональное поле (пусто = без лимита).
- **Доступ:** `club_admin`, `club_moderator`, `super_admin`. За фича-флагом `groups`.

## Часть 1. Модель данных (новые таблицы)

### 1. `club_groups` — группа
```
id
club_id              FK clubs, cascadeOnDelete
name                 string
coach_id             FK users nullable, nullOnDelete   // тренер по умолчанию (юзер-тренер клуба)
price_per_session    decimal(10,2) default 0
capacity             unsignedInteger nullable          // опционально, пусто = без лимита
status               enum('active','archived') default 'active'
note                 text nullable
timestamps
index [club_id, status]
```

### 2. `club_group_members` — участник группы
```
id
group_id    FK club_groups, cascadeOnDelete
client_id   FK club_clients, cascadeOnDelete
status      enum('active','inactive') default 'active'
timestamps
unique [group_id, client_id]
```

### 3. `club_group_enrollments` — пакет (предоплата занятий)
```
id
group_member_id  FK club_group_members, cascadeOnDelete
sessions         unsignedInteger              // куплено занятий
amount           decimal(10,2) default 0       // сумма пакета
is_paid          boolean default false
payment_method   string nullable
created_by       FK users nullable, nullOnDelete
timestamps
index [group_member_id]
```
**Остаток занятий участника** = `SUM(enrollments.sessions)` − `COUNT(attendance where charged = true)` по этому участнику. Считаем на лету (без денормализации на старте).

### 4. `club_group_sessions` — занятие (сессия)
```
id
group_id          FK club_groups, cascadeOnDelete
court_id          FK courts, cascadeOnDelete
court_booking_id  FK court_bookings nullable, nullOnDelete   // связанная бронь, резервирует слот
date              date
start_time        time
end_time          time
coach_id          FK users nullable, nullOnDelete
status            enum('planned','held','cancelled') default 'planned'
held_at           timestamp nullable
conducted_by      FK users nullable, nullOnDelete
timestamps
index [group_id, date]
index [court_id, date]
```

### 5. `club_group_attendance` — посещаемость
```
id
session_id        FK club_group_sessions, cascadeOnDelete
group_member_id   FK club_group_members, cascadeOnDelete
attended          boolean default false
charged           boolean default false        // списано ли занятие из пакета
note              string nullable
timestamps
unique [session_id, group_member_id]
```

### Связь с расписанием кортов
Сессия резервирует корт через **связанную обычную бронь** `court_bookings`:
- при создании сессии создаём `CourtBooking`: `booking_type='group'`, `price=0`, `status='confirmed'`, `client_name` = название группы, `booked_by` = текущий админ, привязка `court_bookings.id → club_group_sessions.court_booking_id`;
- проверка занятости корта при создании сессии — та же, что у обычной брони (нельзя поверх другой брони/блокировки/сессии);
- при отмене сессии (`cancelled`) связанную бронь отменяем/удаляем → слот освобождается;
- благодаря этому расписание, занятость и конфликты работают без переделок; в расписании слот показывается как `booking_type='group'`.

### Модели (app/Models)
- `ClubGroup` (hasMany members, sessions; belongsTo club, coach)
- `ClubGroupMember` (belongsTo group, client; hasMany enrollments, attendance) + аксессор `remaining`
- `ClubGroupEnrollment` (belongsTo member)
- `ClubGroupSession` (belongsTo group, court, coach, courtBooking; hasMany attendance)
- `ClubGroupAttendance` (belongsTo session, member)

## Часть 2. Веб-админка (разделы и флоу)

### Раздел «Группы» (`/club/groups`)
- **Список групп:** название, тренер, кол-во активных участников, цена/занятие, статус. Кнопка «Создать группу».
- **Создание/редактирование группы:** имя, тренер по умолчанию, цена за занятие, вместимость (опц.), заметка, статус.
- **Карточка группы** (`/club/groups/{group}`):
  - Участники: имя клиента, остаток занятий, оплачено/долг, кнопки «Продлить» (новый пакет) и «Убрать из группы».
  - Кнопка «Добавить участника» → поиск по CRM-клиентам + поле «кол-во занятий» (+ авто-сумма = N × цена, редактируемая, чекбокс «оплачено»).
  - Список занятий группы (запланированные/проведённые) — ссылки в «Журнал занятий».

### Добавление клиента в группу
Доступно из карточки группы И из карточки клиента (кнопка «Добавить в группу»):
- выбрать группу (если из клиента) + кол-во занятий + сумму (предзаполнена) + «оплачено»;
- создаёт `club_group_members` (если ещё не участник) + `club_group_enrollments` (пакет);
- если задана вместимость и достигнута — не даём добавить.

### Раздел «Журнал занятий» (`/club/group-sessions`)
Главная рабочая точка.
- **Список сессий:** фильтры по дате/группе/тренеру/статусу. Колонки: дата, время, группа, тренер, корт, статус, пришло/всего.
- **Создать занятие:** группа + корт + дата + время (+ длительность/время окончания) + тренер (по умолч. из группы). Проверка занятости корта. Создаётся `club_group_sessions` + связанная бронь.
- **Карточка занятия / проведение:**
  - Ростер участников группы (активных) с остатком занятий.
  - По каждому: ✅ пришёл / ❌ нет; опц. «пришёл, но не списывать» (`charged=false`).
  - При «пришёл» с `charged=true` и остатком 0 — **блок** (надо продлить).
  - Кнопка **«Провести занятие»** → `status='held'`, `held_at`, `conducted_by`; для отмеченных списываются занятия (создаются строки attendance с `charged`).
  - Кнопка **«Отменить занятие»** → `status='cancelled'`, связанная бронь отменяется, списаний нет.
  - Запись в `ActivityLog` (проведено/отменено).

### Карточка клиента — блок «Группы»
В существующей карточке клиента (`Club\ClientController@index`/show) добавить блок:
- группы клиента, остаток занятий по каждой, история посещений (проведённые сессии);
- кнопка «Добавить в группу».

### Навигация
Пункты сайдбара «Группы» и «Журнал занятий» (`layouts/app.blade.php`) для admin/moderator, за `hasFeature('groups')`.

### Фича-флаг
Добавить фичу `groups` (по умолчанию ВКЛ, как `clients`), переключаемую в супер-админ форме клуба и в дефолтах `Admin\ClubController`. Роуты под middleware `club.feature:groups`.

## Часть 3. Доступ и резолв клуба
Как в существующих Club-контроллерах: `getClub()` (moderator → moderatorClubs, admin → adminClubs, super → первый/по контексту). Проверка, что группа/сессия/клиент принадлежат клубу (иначе 403).

## Не входит в первый этап
- Приложение (самозапись игроков на группы), мобильный API.
- Повторяющиеся группы / авто-генерация сессий по расписанию.
- Отдельный модуль абонементов (пакеты живут внутри группы).
- Возвраты/переносы занятий со снятием списания, перенос остатка между группами.
- Отдельные отчёты по группам (данные готовы — добавим следующим этапом: загрузка тренера групповыми, продажи пакетов в финансах, посещения в карточке клиента уже будут).

## Тестирование (PHPUnit)
- Создание группы; добавление участника + пакет → остаток = N; сумма = N×цена.
- Создание сессии → создаётся связанная бронь, корт занят (конфликт с обычной бронью на это время).
- Проведение: «пришёл» списывает 1 занятие (остаток N→N−1); «не списывать» не списывает; при остатке 0 «пришёл» блокируется (422/ошибка).
- Отмена сессии → связанная бронь отменена, списаний нет, остаток не изменился.
- Доступ: чужой клуб → 403; фича `groups` выключена → 403.
- «Продлить» (новый enrollment) увеличивает остаток.
